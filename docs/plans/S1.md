## Review Focus
- SKU with 1–6 in-stock days and 1 sale → must not produce a huge rate (shrink it; `basis="shrunk"`).
- Store that never ranged a style (no sales in 365 d, style not new) → `vel_daily = 0`, `basis="not_ranged"` (otherwise peer fallback inflates demand everywhere and the chain total blows past 450/day).
- Style sold out everywhere in the window (KUR-18, MOJ-03…) → demand must not read as 0 at stores that sold it last year (`basis="history"`). "Zero sales isn't always slow."
- `oldest_received` blank (on_hand 0) → `age_days` NaN, never an error.
- Week rows where sales happened but `days_in_stock = 0` (191 units) → in-stock days counted as at least the number of days with a sale.

@pytest.fixture(scope="module")
def vel(data):

def _row(vel, store, sku):

def test_chain_forecast_sanity(vel):

- [ ] **Step 2:** run → FAIL.
- [ ] **Step 3: Implement `compute_velocity`.** Window = 84 days ending `as_of` (matches `stock_weekly` weeks ending 2026-08-15 … 10-31). Per store×SKU:
  1. `sold_84`; `in_stock_days = max(Σ weekly.days_in_stock, number of distinct sale dates)`.
  2. If `in_stock_days >= 7`: `rate_instock = sold_84 / in_stock_days`, else 0.
  3. Shrink toward a prior: `prior = peer_rate` (mean `rate_instock` of same-tier stores in the same zone, else same tier, using only rows with `in_stock_days >= 7`); if no peer has it, `prior = style_rate_store × size_share` (size_share = chain 365-d share of that SKU within its style). `w = in_stock_days / (in_stock_days + 28)`; `base = w·rate_instock + (1−w)·prior`. `basis = "instock"` if w ≥ 0.5 else `"shrunk"`. (LKO-01 had KUR-04-L in stock 1 day and sold 3 — its S++ peers PAT-01/BLR-01/BLR-02 sell ~1.6/day of it; the prior is what makes LKO-01 look under-served.)
  4. If `in_stock_days == 0`: (a) BLR-05 (opened < 90 d before as_of) → mean base of same-tier South stores × volume ratio, `new_store_peer`; (b) style launched < 60 d before as_of OR store sold the style in the last 365 d → peer = mean base of same-tier stores in same zone (else same tier) for that SKU, `peer`; if peer is also 0 → own 365-d rate before the window (`sold_365 / 365`), `history`; (c) otherwise `vel 0`, `not_ranged`.
  5. `vel_daily = base × lift[state of store]`.
  Tune only within these rules until the sanity band passes; note any constant you pick in the commit message.
