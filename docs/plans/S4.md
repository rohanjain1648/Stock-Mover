**Goal:** A FastAPI service that runs the engine on a schedule, serves the latest run, records approve/reject decisions, exports the approved list, builds notifications (email digest + ≤5 alerts per area manager per week), and is live on Render with a GitHub Actions daily trigger.

**Architecture:** `backend/app/` package: `main.py` (FastAPI app, routes, CORS, lifespan), `store.py` (SQLite: runs, decisions, alerts_sent, notif_log), `runs.py` (calls `engine.run.run_engine`, keeps the last *passing* run live, falls back to `contracts/sample_run.json` with `is_sample` true), `notify.py` (C4 builder + Gmail SMTP), `scheduler.py` (APScheduler 07:00 Asia/Kolkata). Pattern borrowed from OptiLogiX `georisk_backend/main.py` (D:\downloads\OptiLogiX-main-code\georisk_backend\main.py): lifespan, CORS, routers.

**Tech Stack:** Python 3.12, FastAPI, uvicorn, pydantic v2, APScheduler, sqlite3 (stdlib), smtplib (stdlib), pytest + httpx TestClient, Docker on Render, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-21-stock-mover-design.md` (§6, §8) and `contracts/CONTRACTS.md` (**C3 is your API — implement it exactly**, C2, C4). Examples: `contracts/sample_run.json`, `contracts/sample_notifications.json`.

## Global Constraints
- API live on Render by **14:45 IST**; freeze 15:30.
- You own ONLY: `backend/**`, `Dockerfile`, `.dockerignore`, `render.yaml`, `.github/workflows/**`. Never edit `engine/`, `contracts/`, `frontend/`.
- Until S2/S3 land, `run_engine(strict=True)` raises `ValidationFailed` (validator missing) — that's expected: serve the sample with `is_sample: true`. Never serve a run whose `validation.passed` is false.
- Env vars: `RUN_TOKEN` (required for POST /api/runs), `FRONTEND_ORIGIN` (Vercel URL), `PUBLIC_APP_URL` (used in digest link), optional `SMTP_USER`, `SMTP_APP_PASSWORD`, `DIGEST_TO`, `AM_EMAIL_<AM-ID>` (e.g. `AM_EMAIL_AM-02` → use `AM_EMAIL_AM_02`, dash→underscore). Missing SMTP → skip sending, log `ok:false, reason:"smtp not configured"`.
- SQLite file `backend/state.db` (gitignored). Decisions keyed by `(run_id, group_id)`; when a new run has the same `group_id` + same `style_id/from/to/qty`, carry the decision over.
- AM cap: per `area_managers.max_alerts_per_week` (5) per ISO week (`YYYY-Www`), counted in `alerts_sent`; an AM's items = groups whose `from` or `to` is one of their stores, highest `priority` first.
- Engine must run in-process with the repo root on `sys.path` (`from engine.run import run_engine, ValidationFailed`).

## Review Focus
- Render free tier sleeps → first request after idle takes ~50 s. Mitigate with the keep-warm workflow (every 10 min) and fast startup (don't block startup on the engine: start serving the last stored run or the sample immediately, run the engine in a background thread).
- POST /api/runs while a run is in progress → second call returns 409 `{"detail":"run in progress"}`, never two concurrent runs (use a lock).
- Decision for an unknown `group_id` → 404, not 500.
- `/api/export.csv` with no approvals → header row only, 200.
- CORS preflight from the Vercel origin must succeed (test with `OPTIONS`).
